# Provisioning an Ubuntu Server

Deployer's `provision` recipe turns a fresh **Ubuntu** VPS into a server ready to
serve a website at your `deploy_path`. It installs PHP, a database, Node.js,
Composer, and the Caddy web server, and configures a deploy user, SSH, and a
firewall.

```php
require 'recipe/provision.php';
```

Framework recipes already pull in `common`, which requires `provision`, so the
`provision` task is usually available without an explicit require.

## Prerequisites

- An **Ubuntu** VPS (Linode, DigitalOcean, Vultr, AWS, GCP, …). Only Ubuntu is
  supported; the recipe warns and asks for confirmation on other OSes or on
  Ubuntu versions older than 20.
- **Root SSH key auth enabled.** Recent Ubuntu images disable it by default —
  enable it before provisioning, then you can disable root SSH again afterward.
- A host defined with at least `remote_user` and `deploy_path`:

```php
host('example.org')
    ->set('remote_user', 'deployer')
    ->set('deploy_path', '~/example');
```

Put your SSH key in `~/.ssh/config` rather than in the recipe:

```
Host *
  IdentityFile ~/.ssh/id_rsa
```

## Running provision

```sh
dep provision
```

It prompts for PHP version, database type and credentials, sudo password,
domain, and public path, then takes about five minutes. If the server only has
`root`, provisioning creates and configures a `deployer` user for you.

## `provision_user` and `become`

`provision_user` (default `root`) is the user the recipe connects as. Each
provision step sets `remote_user` to `provision_user` for the duration of
provisioning. Override it from the CLI to connect as a non-root user, and use
`become` to escalate to root:

```sh
dep provision -o provision_user=your-user
dep provision -o become=root
```

## What the provision task does

`provision` is a group task running these steps in order:

1. `provision:check` — verifies the OS is Ubuntu (≥ 20); aborts otherwise unless
   confirmed. Runs once per node.
2. `provision:configure` — collects required params (`sudo_password`, `domain`,
   `public_path`, `php_version`, `db_type`, and DB credentials unless
   `db_type` is `none`) and prints a `host(...)` config snippet so you can pin
   the answers in `deploy.php`.
3. `provision:update` — adds the `ondrej/php` and Caddy apt repositories and
   runs `apt-get update`.
4. `provision:upgrade` — `apt-get upgrade -y`.
5. `provision:install` — installs the base packages (Caddy, git, redis,
   fail2ban, ufw, Node.js, build tools, sqlite, etc.).
6. `provision:ssh` — disables SSH password authentication and restarts SSH.
7. `provision:firewall` — `ufw` allows ports 22, 80, 443 and enables the
   firewall.
8. `provision:user` — sets up the deployer user (see below).
9. `provision:php` — installs PHP packages for the chosen `php_version`.
10. `provision:node` — installs Node.js (`node_version`).
11. `provision:databases` — provisions the chosen database.
12. `provision:composer` — installs Composer.
13. `provision:server` + `provision:website` — configure Caddy and the site.
14. `provision:verify` — fetches `{{domain}}` and reports success.

## Configuration steps

### PHP — `provision:php`

Set `php_version` per host (it is autogenerated/prompted otherwise). It also
provides `logs:php-fpm` to follow php-fpm logs and `provision:composer` to
install Composer.

```php
host('example.org')->set('php_version', '8.3');
```

### Databases — `provision:databases`

`db_type` selects the engine; the recipe has dedicated steps
`provision:mysql`, `provision:mariadb`, and `provision:postgresql`. Credentials
come from `db_name` (default `prod`), `db_user` (default `deployer`), and
`db_password` (hidden prompt). Set `db_type` to `none` to skip database setup.

```php
set('db_type', 'mysql');
set('db_name', 'prod');
set('db_user', 'deployer');
```

### Node.js — `provision:node`

`node_version` defaults to `--lts`. Override to pin a major version.

```php
set('node_version', '20');
```

### User — `provision:user`

Creates the deployer user, prompting for `sudo_password` (hidden). Also provides
`provision:ssh_copy_id` to copy your public key to the server.

### Website + Caddy — `provision:server` / `provision:website`

The recipe configures **Caddy** automatically and serves the site from
`public_path` under the current release, so no manual web-server config is
needed. Two settings drive it:

- `domain` — defaults to the host's `hostname`.
- `public_path` — defaults to `public` (framework recipes may override it, e.g.
  Laravel sets `public`).

```php
set('domain', 'example.org');
set('public_path', 'public');
```

Inspect web-server logs afterward with `logs:access` and `logs:caddy`.

## After provisioning

Provisioning installs everything needed to serve a site at `deploy_path`. You
can then deploy with `dep deploy`. To prefill the prompts on future runs, copy
the `host(...)` snippet that `provision:configure` printed into your
`deploy.php`.
