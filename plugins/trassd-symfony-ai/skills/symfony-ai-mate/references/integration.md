# Mate — assistant integration

Mate serves over **stdio**. Every assistant runs the same underlying command:
`php /absolute/path/to/vendor/bin/mate serve`. Always use absolute paths —
relative paths commonly fail.

## Claude Code

```terminal
$ claude mcp add mate $(pwd)/vendor/bin/mate serve --scope local
$ claude mcp list   # Verify: mate - ✓ Connected
```

Re-add if needed:

```terminal
$ claude mcp remove mate
$ claude mcp add mate $(pwd)/vendor/bin/mate serve --scope local
```

## Claude Desktop

Edit the config (Settings > Developer > Edit Config), or directly:

- macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
- Windows: `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
    "mcpServers": {
        "symfony-ai-mate": {
            "command": "php",
            "args": ["/absolute/path/to/vendor/bin/mate", "serve"]
        }
    }
}
```

Save and restart Claude Desktop.

## JetBrains AI Assistant

Settings → Tools → AI Assistant → Model Context Protocol (MCP) → Add:

- Name: `Symfony AI Mate`
- Command type: `stdio`
- Executable: `php`
- Arguments: `/absolute/path/to/vendor/bin/mate serve`

## Codex

Codex does **not** read this project's `mcp.json`. Use the wrappers generated by
`mate init`, which pass runtime `-c mcp_servers...` options so no persistent Codex
config is written:

- macOS/Linux: `./bin/codex`
- Windows: `bin/codex.bat`

```terminal
$ ./bin/codex
```

If Mate tools don't show, run `vendor/bin/mate discover` to refresh extension and
agent instructions, and confirm the wrapper scripts exist.

## Debug logging via the assistant

Pass env vars in the assistant's server config to capture logs even when stderr
isn't visible:

```json
{
    "mcpServers": {
        "symfony-ai-mate": {
            "command": "php",
            "args": ["vendor/bin/mate", "serve"],
            "env": { "MATE_DEBUG": "1", "MATE_DEBUG_FILE": "1" }
        }
    }
}
```
